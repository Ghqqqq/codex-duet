# Changelog

## 1.4.7

### Stability fixes

- A finished native worker's report is no longer held back by a stuck progress lookup. Handle and status lookups use one 15-second bound, and the turn's own result is delivered even if a lookup never returns.
- A native follow-up admitted while the previous turn's cancellation is confirmed keeps that confirmation. The admission commit now rebases onto the latest binding inside its per-binding write slot, after pruning, and charges its real byte delta.
- Starting a new task on a stopped native worker clears the stopped turn's cancellation. A completed follow-up then leaves room for new agents as ordinary finished history, instead of staying protected and causing `native_capacity`.
- Native spawn observations age with the 24-hour orphan-guard window, so guards whose start never produced a binding are reclaimed without a reload.
- A companion reply with a missing or unknown status is treated as a protocol error. The turn stays unresolved and blocked instead of being recorded as answered.
- A failing progress or log write (for example a full disk) no longer crashes a worker from its heartbeat or leaks a runtime after initialize, and no longer turns a committed completion into `failed`. Progress and log output are best effort. Newly learned thread/turn handles are retried with later progress until stored.
- Automatic stops are rechecked under the state lock before they cancel. Lease expiry, owner loss and owner stops need the same owner and attachment and a still-true condition, so a renewal or adoption that lands after the watchdog's read keeps the job running. SessionEnd cancels only jobs still owned by the ending session. Explicit `duet cancel` is unchanged.
- Retention connects to the broker before its final reference and rollout check, so a follow-up queued while that connection starts keeps its thread. A live worker or launcher PID on either the index entry or the job record now protects a job in every record shape.

### Commands and reports

- `duet status <job> --wait --owner <id>` renews that owner for the whole wait, instead of once at the start.
- `wait` on a native review reports the review's own status, so a successful review returns `completed` (exit 0) as `result` does.
- `next` and `continuationCommand` offer `task --to`/`task --continue` only for task jobs with a recorded thread. Reviews and jobs that never started a thread get `null`. Auth blockers still suggest `duet setup`, and context or provider blockers on task jobs suggest `duet task --fresh`.
- `result --details` and `wait --details` carry every stored blocker with its full message. Compact reports keep their bounded projection.
- A single, already-quoted argument is no longer split again, so `--cwd='/path/with spaces'` works. Raw strings are split only for `--args-stdin`.
- A value option followed by another recognised option or `--` (for example `--model --fast`) is a missing-value error before anything is dispatched. Use `--opt=value` for a value that starts with `-`.
- `ultra-codex status` and `off` reject `--quick`, `--thorough` and `--max-workers`; `on` and `off` reject `--for-command`.
- Native capacity, binding-gone and late-answer reports render as readable markdown in the agent view.

### Known limits

- Between retention's final recheck and its `thread/delete` request, another process can still publish a follow-up for that thread. The window now spans only the request itself.
- A recycled PID that matches a recorded worker or launcher PID keeps that job until the process exits.

## 1.4.6

### Stability fixes

- A broken app-server pipe no longer crashes the worker or broker. Each runtime stdin and broker socket now has an error listener installed before its first write. An asynchronous EPIPE, a closed stdout or a closed socket settles the connection as a transport loss, rejects pending requests and cleans up the owned process group once. A runtime that exits keeps its exit code or signal in the error even when stdout closes first, and closing a direct runtime waits up to 500 ms for its exit. Group cleanup tolerates the EPERM that macOS returns for a group holding a zombie, and then signals a not-yet-reaped leader directly.
- `initialize` has a default 60-second deadline, shared by broker startup, the busy-broker direct fallback and the direct connection. `CODEX_COMPANION_CONNECT_TIMEOUT_MS` changes it for tasks, reviews and transfers. On expiry the owned runtime is stopped and the connection fails with `ETIMEDOUT`. No task work is replayed.
- Outbound writes to each runtime, broker client and broker peer go through an ordered queue that honours `drain`. A peer whose backlog would exceed 32 MiB is disconnected with `CODEX_TRANSPORT_BACKPRESSURE`, and the broker and other peers keep running. A single frame of any size, for example a long `thread/read`, is still delivered to an idle peer, and frames behind it are not counted against the cap while it drains. A healthy broker-client close still delivers accepted frames within 300 ms; a broken transport closes at once. Runtime stderr keeps only a 64 KiB tail with a truncation marker; startup-warning detection uses that tail.
- Cancellation and lease expiry always abort the running turn, even when recording the interruption fails (for example, a full disk). A writer that still cannot read or parse `state.json` after brief retries no longer publishes an empty index. It keeps the unreadable file as `state.json.unreadable-<time>`, rebuilds the index from the job records, publishes it before applying its own change, warns on stderr and continues, so running workers keep their progress, lease and ending. Job records are retried too; one that stays unreadable is left out until its next update. If no copy of the old index can be kept, the write fails and the index is left untouched. Read-only status and listings still degrade without writing. A crash between a job-record write and its index commit is repaired by that job's next update.
- Native admission inventory and commit are serialized across agents in one adapter, so concurrent starts can no longer exceed the 128-binding or 2 MiB store budgets. Per-agent waits and recovery lookups stay outside that queue, so a slow agent does not spend another agent's `turn.start` budget; the commit rebases onto the latest binding, so a cancellation confirmed meanwhile is kept. Each turn owns its binding: a late heartbeat, notice or cancellation callback from an earlier turn can no longer overwrite a follow-up that was already accepted. A failed progress notice or progress store write is logged and no longer closes the owner stream; launch and ownership writes still fail the turn. Spawn guards whose `turn.start` never produced a binding count toward the store budget and are reclaimed after a day, so a delayed first start after a reload keeps its native identity.
- A follow-up's admission check reads its predecessor's thread through a private runtime when the shared broker is streaming another job. Before, a follow-up to a worker whose turn end was still unconfirmed was refused with `thread_busy` while another worker in the same workspace was running, because the check could not read the thread. Status and maintenance reads keep the cheap refusal.
- Retention keeps a job whose private record is missing unless its index shows a terminal status, has no protection and every recorded timestamp is past the cutoff. A live launcher PID also protects a job. Name reservations of expired sessions are retired once the session has no surviving job and no live writer; stale claim temporaries are removed too.
- A journal append that fails or is torn no longer poisons the run. A failed write rolls back to the last complete row, and readers ignore an incomplete final line, which the next locked append removes.
- codex-live releases the full payloads of unselected jobs after projecting them and keeps raw payloads in an 8 MiB cache, evicting the least recently used. Selecting a job reloads its details.

### Run journal

- Verdict criteria accept any id of one to four uppercase letters followed by digits (for example `F3`, `S1` or `AC2`) followed by `:` at the start of a declared criterion, in addition to `K<n>`, which keeps its 1.4.5 forms.

### Known limits

- Admission and binding writes are serialized within one adapter module. A store write already in flight in a module from before `/reload-plugins` is not ordered with the new module: in that window a late cancellation write can still replace a just-admitted follow-up, and two admissions can slightly exceed the budgets.
- A 1.4.5 follow-up admitted just before upgrading, then rejected before it starts (for example an invalid `DUET:` line), reports a generic hook failure once.
- When the codex-live selection changes while a poll is publishing, the newly selected job can show without details for one poll.
- A missing private record now keeps a stale `running` index entry until recovery or manual cleanup. 1.4.5 deleted it at the first age cleanup.
- Rebuilding an unreadable index drops what only the index held: settings such as the review gate return to defaults, and jobs without a job record disappear from listings. Both remain in the kept file.
- Name reservation and retirement share one lock. A slow retirement pass can push a native name reservation past its two-second budget; the Agent call then keeps its passed name.

## 1.4.5

### Stability fixes

- Inferred turn completion is checked against the exact server turn through a bounded `thread/read`. If the turn is still running or cannot be confirmed, the captured answer remains available but the job stays unresolved, protected from pruning and eligible for recovery or cancellation. When the broker interrupts a leftover turn after a captured answer, reconciliation keeps the job `completed` unless there is a recorded stop intent or an owner detach other than `returned`, even while the owner is still attached. `duet cancel` and worker-runtime stops persist their intent before interrupting; explicit cancellation stays `cancelled`, owner stops stay `interrupted` and failed turns stay `failed`.
- Broker shutdown is idempotent and tolerates an app-server that has already exited, completing socket/file cleanup instead of crashing on a request to the closed client. Transport loss followed by a confirmed persisted `interrupted` turn reports `blocked` (exit 2) with `codex_runtime_restarted` and a continuation, unless a recorded Duet stop takes precedence. The thread and saved work persist; no turn is rerun automatically. A ChatGPT desktop auto-update stopping app-servers launched from its managed CLI was one observed cause. Setup warns with `desktop_managed_codex_runtime` for a CLI under `~/.codex/plugins/.plugin-appserver/` or `ChatGPT.app/Contents/Resources/codex-cli/`, including resolved symlinks. Pin a stable CLI with `CODEX_COMPANION_BIN` or `runtime.json`'s `codexBinary`; the warning neither changes the pin nor makes `ready` false.
- Native admission reclaims finished history oldest-first to make room within the 128-binding and 2 MiB store budgets, so ordinary finished history no longer consumes active admission capacity. Unconfirmed cancellations remain protected from pressure eviction until the turn is proven ended or the seven-day age expiry. Timestamped spawn guards protect bindings awaiting `turn.start` for ten minutes; legacy never-started bindings receive ten minutes from first observation before yielding to pressure, after finished history. Active turns and pending questions remain protected. Briefs over 65,536 characters are refused before eviction, and every admission refusal clears its spawn guard. An evicted binding returns `native_binding_gone`; use a new native agent.
- Session-start prewarm now runs bounded stale-job maintenance independently of the 12-hour age-cleanup interval: at most five recovery attempts within a five-second pass. Only nonactive unresolved tasks with recorded thread/turn handles, no attached owner or live worker/launcher and sufficiently old activity/leases qualify. The minimum age is 30 minutes or the lease plus one minute, whichever is longer. Exact terminal evidence is reconciled without rerunning; unavailable or still-running turns stay unchanged. Orphan markers are removed only after their owned job path is proven missing in readable directories. A persisted scan cursor reaches every session folder across bounded passes, and retention removes markers for jobs it deletes even when the markers are newer.
- Brokers retire abandoned turns promptly once no client remains, after the four-second interruption grace. Connected peers are preserved; abandoned turns are retried after 30 minutes and no longer prevent later idle retirement. Interrupt acknowledgements are logged separately from confirmed completion.
- `task --cwd <repo>/sub` now starts and resumes the Codex thread in that subdirectory. Broker and job state still belong to the repository root; reviews still run at the root.
- Long native turns keep streaming. After the 200-notice cap, deduplicated lines or live-only command starts, a busy job could stream nothing until Claude Code's 600-second stall watchdog killed the agent and interrupted its Codex job. The heartbeat now streams a keepalive whenever nothing streamed for 30 seconds, even when its durable notice is suppressed or the handle lookup fails. At most one keepalive publication is pending, so a slow reader does not accumulate blocked publications.

### Native dispatch and worker names

- Native dispatch is the default from the first assignment, without waiting for a readiness notice. SessionStart and the persistent `codex:native-dispatch` guidance agree: background `duet task` is for `native_adapter_unavailable`, `native_capacity`, per-call options the `DUET:` line rejects, or follow-ups to Bash-launched workers. Browser and Computer Use tasks run natively. The fallback report now says to run `/reload-plugins`, check `duet status` before retrying and use background `duet task` if the hook still fails; an older in-memory build, unloaded hooks or a hook failure can all reach it.
- `agent.spawn` returns after recording the agent type and a small guard; `turn.start` owns admission, eviction and the durable binding. The first turn is recognized before the host lists the agent, and a surviving guard keeps a reload from falling through to the model.
- Every fresh native Agent call reserves a scientist pool name through `reserve-name` before spawn, replacing a passed label unless it is a free pool name; resumptions keep their name. Dispatch claims the reservation atomically, keeping the agent, pane and report aligned. When the assigned name differs from the input, the Agent result carries a `Codex worker named X` note for SendMessage follow-ups (as tool-result context Claude reads, including for background launches); a preserved free pool name needs no extra note. Reservation uses cached host Node within a two-second budget; on failure the Agent call passes through unchanged. `duet task --name <label>` still requests a name for a fresh thread; collisions fall back to the pool and follow-ups keep their name. Names use 1–64 ASCII letters, digits, `_`, `.` or `-`, starting with a letter or digit. The job-ID prefixes `task-`, `review-` and `job-` are refused publicly (case-insensitive) and ignored by internal native naming.

### Commands and run journal

- `/codex:transfer`, `/codex:status`, `/codex:result` and `/codex:cancel` pass raw arguments through `--args-stdin` and a single-quoted heredoc. The companion parses them without shell expansion, so quoted paths with spaces work. Reviews retain their separate literal-focus parsing rules.
- Journal validation reports `unrecorded_finish` when a linked job has a readable terminal record but no `job_finished` row, and also `no_verdict` when no verdict exists. A passed close remains blocked even if a verdict was written first. `duet result <jobId> --details` retries finish recording; missing or unreadable job records still cannot prove an ending.
- `journal use <runId>` selects an existing open run for the current session, including across workspaces. Without an active run, add, close and task linking use the sole open run in the current workspace; several open runs leave tasks unlinked and make add/close request `journal use <runId>` or `--run <id>`. The fallback does not change the active pointer. Verdict `resolves` accepts job IDs linked to that run regardless of session. Verdict criteria accept declared exact text, a unique shown prefix ending in `…`, or a unique `K<n>` ID (optionally followed by `:`) already present at the start of a declared criterion. Unknown or ambiguous criteria are rejected; add new criteria with `journal add criteria`. Historical verdict-only criteria keep their prior validation behavior.

### Activity and live pane

- Native progress appears under the Agent row in the main transcript (the three latest entries, name, model, effort, speed and elapsed time) and under each turn's prompt row in the agent view (up to 40 entries), with colours matching `codex-live`. The turn log is bound to the prompt row's appended `uuid`, so identical briefs keep separate logs; same-title starts and completions merge FIFO. Unobserved rows, including after reload, render without a log. The agent-view spinner shows `<worker> · running · <elapsed>`, and the `DUET:` flag line draws as a compact `Codex · model · effort · speed · sandbox · folder` header, showing only supplied settings and `fork` when requested. The agent view renders the report as readable markdown. These views do not rewrite the recorded transcript or the report handed back to Claude; command-start lines are live only, while completion notices remain durable.
- Progress uses pane-style names: `Bash(<cmd>) · Done (21.1s)` or `Bash(<cmd>) · Error: exit N`, `Update(path) · +a −r` (or `Write`/`Delete`), `server - tool (MCP)` and `Update Todos`. Recognized leading environment prefixes and shell wrappers are omitted from command display; captured verification keeps the full commands. Paths inside the job's cwd are relative to it; paths outside remain absolute. Durations below one second are omitted, and missing command exits say `exit unknown`.
- `codex-live` accepts Windows drive and UNC job/workspace paths and uses `USERPROFILE` when `HOME` is absent. It removes a job only after two ENOENT observations at least five seconds apart with the session inventory and jobs directory readable and the filename absent from that directory, or when a readable marker inventory proves its marker gone. Removal also clears stale pane metadata. Transient read failures, unreadable directories or a folder still listing the file keep the last good view.
- Known limits: the native views are bounded display projections, so use result details for full evidence. Stale-job maintenance is bounded and conservative; missing handles or unreadable history still require explicit recovery. Each progress event still rewrites the whole job record.
- Known limits: desktop-managed Codex CLIs can be stopped by desktop-app updates. Setup warns but does not re-pin the runtime; use a stable CLI pin. A runtime exit without readable terminal evidence stays unresolved until recovery can confirm the turn.

## 1.4.4

### Reports and recovery

- On a typed prompt, Claude now receives one recovery line for up to five tracked jobs in the session that ended at least 10 seconds earlier without an emitted report, previous notice or live attached owner wait. New tasks carry `reportTracking: 1`; terminal delivery records `reportEmittedAt`, and notices record `endingNoticedAt`. Pre-1.4.4 jobs are excluded. Lookup errors, oversized state or a 2-second lookup timeout leave the prompt unchanged; scans cap at 256 state-root entries and 8 MiB of indexes (2 MiB each). Notices are claimed under the job lock with a random token before they are attached, confirmed after the prompt is accepted and released if it is dropped, so a report delivered first suppresses the notice. Unconfirmed claims expire after 10 minutes: a crash, lost response or failed release delays a notice. An accepted notice whose confirmation failed is confirmed silently when claimed again, so it repeats at most once per hook instance (for example after a plugin reload). Task-notification attachments are marked delivered only after the prompt is accepted. Notice fields are display-cleaned. The helper adds an estimated 60 ms per typed prompt, varying by machine and state.
- Failed turns with Codex errors `cyberPolicy`, `usageLimitExceeded`/`sessionBudgetExceeded`, `contextWindowExceeded` or `unauthorized` now report `blocked` (exit 2), adding actionable `provider_refused`, `usage_limit`, `context_window_exceeded` or `auth_required` blockers respectively. The only text fallback is “flagged for possible cybersecurity risk”, used when typed information is absent. Details retain the original `error` text with display cleanup; other failed turns remain `failed` (exit 1). An error notification followed by a successful turn does not alone trigger a runtime blocker.

- Native dispatch is now preferred for the whole session. After a complete registration, the native adapter adds a `codex:native-dispatch` system-prompt section (`prompt.compose`, session scope, only on requests that offer the Agent tool). It asks for `codex:codex-native` first, says browser work and Computer Use run natively (unapproved apps arrive as approval questions answered through SendMessage), and keeps background-Bash `duet task` for `native_adapter_unavailable`, per-call overrides the `DUET:` line rejects and follow-ups to Bash-launched workers. Previously the one-time readiness notice was lost on compaction while the Bash-only SessionStart recipe came back, so Claude drifted to Bash. SessionStart still cannot tell whether the adapter registered: it keeps the Bash recipe, now framed as the fallback, and never names the native agent.

### Stability fixes

- A task dispatch can no longer run twice. Under load the detached launcher could time out after its worker had already started, and its fallback then started a second worker for the same job. Each task-worker now atomically claims its queued job (`executionClaim`) before starting a turn; a second worker exits 0 without running, and a dead worker's claim is reclaimable only while the job is still queued.
- Delivery marks are more reliable. A native worker stopped during startup no longer marks a report Claude never received, so its ending gets one recovery notice. Index reads retry briefly when a concurrent write replaces the file, instead of dropping a delivery mark and later announcing a delivered ending.
- Typed runtime blockers point at their recovery. `context_window_exceeded` and `provider_refused` suggest `duet task --fresh` (or a new native agent) instead of continuing the same thread, `auth_required` suggests `duet setup` (`/codex:setup` natively), and `usage_limit` keeps the follow-up.
- Errors give runnable recovery. `wait`, `answer` and `cancel` no longer suggest an unsupported `--thread`; they suggest the positional job ID and `duet status --all`. A rejected answer keeps the job's identity with an observational `next`/`details`, and a closed `--run` names its three recoveries. A recovery command that would push a compact report past its 2,000-byte envelope (for example a very long workspace path) is omitted, so the report is still delivered with its `details` command.
- The live pane hides an unanswered question once its deadline passes, matching the companion. A closed pane no longer re-lays out an unchanged transcript every second, which cut a large selected transcript from about 110–350 ms to about 5 ms per poll. Input-attention headers use the warning colour, and the footer shows the first blocker code, for example `Needs your attention (provider_refused)`.
- Packaged agent, command and skill guidance now links to the published approval docs instead of repository paths that the installed plugin does not contain.
- Known limits: each progress event still rewrites the whole job record, so long message-heavy jobs write far more than they add (a split activity log is planned). Journals that use 1.4.4 withdrawals show those criteria as unchecked again if rolled back to 1.4.2.

### Run journal

- `journal add withdraw` accepts known exact criterion text and a reason. Withdrawn criteria show as `withdrawn` with that reason and no longer produce unchecked/unmet issues; other job issues remain. A later `add criteria` with the same text reactivates them.
- `journal start --switch` leaves the previous run open, selects the new run for the session and returns `previousRunId`. Ordinary starts still reject an already open active run; use switching for an unrelated task the user starts mid-run.
- `task --run <id|none>` overrides journal linkage for one dispatch only; follow-ups do not inherit it. `none` skips linking. An explicit run resolves across workspaces in the isolated home and must be open; invalid, closed or failed explicit linkage stops dispatch before a worker starts and removes the rejected reservation, including a newly reserved worker name, so the thread stays free for a retry. If the link succeeded before a later write failed, the run records that job as failed so validation asks for a verdict.

### Activity and live pane

- Job records now retain only the newest 500 activity events, with cumulative `activityTotals.events` and `activityTotals.toolUses`; legacy records seed totals once from their remaining events. Result details use the total for `activityCount` unless the payload already supplies a count; compatibility waits keep their per-wait count and add events evicted before they read them to `activityCount`/`activityOmitted`, reported separately as `activityEvicted`. The pairing state stays out of the job index, status and result output. The pane and `/codex:status` feed show retained events only. Pairing keeps at most 100 hashed pending tool identities; eviction can overcount by one per later completion whose start was forgotten, including multiple starts under one identity.
- The pane distinguishes `Question for Claude`, `Needs your attention` (`needs_input` in warning colour, `blocked` in error colour) and `Outcome unknown`, with separate status-line counts; non-question waits keep `Waiting for Claude`. Tool counts prefer `activityTotals.toolUses`. The hidden-finished notice follows Duet cleanup settings, and a selected name ending in `-N` gets a name-reuse hint when the pane has more than one body row. Individual unfinished tool entries in unresolved turns still say `Unresolved`.

## 1.4.3

### Dispatch, results and recovery

- A foreground job (`task --json`, a foreground review or the Stop-gate review) now stops with `parent_exit` when the process that launched it dies, including during startup before its turn begins, instead of renewing its own lease until the Codex turn ends. A closed stderr pipe no longer prevents the interrupted state and journal finish from being recorded.
- A refused follow-up on a busy thread now points to the owning job's question-pinned answer, otherwise its recovery/status action, or null. It no longer suggests another task on that busy thread. CLI, delivered and native reports retain the owner's nested question and cancel action; details still select the refused attempt.
- Status filters the selected session before history limits, so other sessions' completions cannot hide its retained jobs. JSON adds `historyOmitted`, and text reports nonzero omissions within that scope.
- Compact blockers keep bounded app/tab/session identifiers, predecessor identifiers and cleanup status when captured, instead of requiring a details read to identify the affected app or tab. Full stored fields remain in details.
- Answer submission, including submit-only calls, rejects an explicit unrelated owner, stopping job or expired lease without changing the pending answer. Retired owners still receive `ownership_moved`.

### Parent questions and approvals

- A late native answer after external resolution or job completion returns the old job with a notice, including after adapter reload. It no longer starts an unintended task; a subsequent new brief can start work. Expiry alone does not trigger that notice: the adapter applies no local expiry check, and an answer to a still-present expired slot is refused by the companion as in 1.4.2.
- Abandoned unanswered questions disappear from answerable snapshots at expiry, no longer make `wait` return early, and can be reclaimed by a new question, preserving `expired` history. Late cleanup cannot erase a successor, and answers accepted before the deadline remain deliverable. Concurrent questions/approvals share one atomic slot: the winner is preserved and the loser receives busy guidance.
- Denied or unsupported non-Computer-Use server requests now force `blocked` (exit 2), even when Codex claims completion. `approval_denied` / `approval_unsupported` retain safe method/kind/server/origin identifiers in compact reports and safe request IDs in details; messages never include request payloads. Unsupported MCP elicitations still return nonpersistent cancel. App refusals keep their existing Computer Use blocker.

### Reviews and instruction forwarding

- Security: the fallback instruction scan no longer follows a repository's symlinked `.claude` or `.claude/rules` out of the repository. Project and local files, rules and `@` imports must resolve inside the ancestor directory that owns them, so a cloned repository can no longer make Duet forward files from elsewhere on disk to Codex as developer instructions. User and managed profiles are unchanged.
- The optional Stop review gate runs at most one review per user turn: a stop that follows a gate block (`stop_hook_active`) is allowed with a note instead of reviewed again. Failed, timed-out or unparseable reviews no longer block the stop; their reason is shown as a note. Only explicit findings from the first review block, so an expired login can no longer trap Claude in a stop/review/block loop.
- Reviews launched from subdirectories now cover and run at the repository root. Default-base detection prefers the local branch named by `origin/HEAD`, with a remote-tracking fallback; invalid bases fail before dispatch instead of producing an empty comparison.
- Untracked review content now has aggregate limits of 256 KiB and 32 files, alongside the existing 24 KiB per-file limit. Omitted paths/sizes/reasons tell the reviewer what to collect itself. Git metadata beyond 8 MiB fails explicitly instead of silently truncating.
- Review templates forward raw `$ARGUMENTS` unchanged; Claude no longer splits options from focus. The companion reads recognized options from the start, then preserves the first focus token and its remaining text in order, including apostrophes, quotes, backslashes, internal spacing and newlines. Exact trailing `--wait`/`--background`/`--json` remain options; explicit `--` keeps its entire tail literal. Typo and missing-value checks apply only in the option prefix, including a missing value immediately before the separator.
- Empty native output and empty, malformed or schema-invalid adversarial output now fail as `review_output_invalid` (exit 1) instead of looking successful. Review jobs save raw/result artifacts, and result details expose complete review text/findings beyond the unchanged compact summary cap.
- Fallback user instructions/rules, auto-memory exclusions, transcript discovery/validation and private import staging/cleanup now follow the selected absolute `CLAUDE_CONFIG_DIR`, including symlinked profiles. When another profile is selected, the ancestor scan skips the unselected `HOME/.claude` by real path, even for workspaces beneath HOME. Missing, empty or relative values fall back to `~/.claude`; transcript sources outside that profile's projects root remain refused.

### Live pane

- Uncleared blocked/needs-input sessions no longer disappear behind twenty ordinary completions. The newest 40 receive additional protection (`ATTENTION_SESSION_LIMIT`), subject to the state budget and existing active/unresolved/selected exceptions; waiting counts include omitted attention. Ordinary finished history yields first when state must shrink.
- Narrow and short panes retain history navigation alongside Clear, with compact `j` / `c` controls when needed, so retained workers remain selectable.
- Directory/new-marker discovery failures now show their own warning even when cached jobs are healthy or the inventory is empty. Repeated failures are deduplicated, recovery clears the warning, and a fresh absent directory remains quiet.
- Malformed persisted pane caches are reset and rediscovered with a repair diagnostic instead of repeatedly failing to poll/render. Job and marker files remain untouched; pane-only selections, anchors and clear tombstones can be lost.

### Orchestration, setup and retention

- Ultra-codex mode now follows one Claude session across workspaces at `<isolated home>/duet/ultra-codex/<session id>.json`; on/off/status, reminders and SessionEnd agree regardless of cwd. Workspace-keyed legacy records are discarded, so enable mode again after upgrading from that layout. The separate fixed 30-day mode cleanup covers both layouts.
- The packaged Codex plugin explicitly declares ES modules, fixing standalone loading when Node's automatic module detection is unavailable; the advertised Node 18.18+ minimum is unchanged.
- Retention and thread inventory now share read-only classification of index-less workspaces. Directories without private job files are exempt. Job-bearing trees stop blocking only when their name and artifact layout are Duet's, jobs are terminal or id-less/unparsable, and there are no live PIDs, broker pointers, open journals, unresolved/attached jobs, pending migrations/writes or recent activity. Retention uses its configured cutoff; recovery inventory uses a 24-hour minimum and preserves valid terminal records for turn attribution. Other job-bearing trees remain with a reason and keep inventory incomplete. Classification takes no state lock, moves or deletes nothing, and allows unrelated thread retention in the same plan once inventory is complete. Cleanup reports `inertWorkspaces` without adding freed bytes/deleted jobs, and text includes a manual `rm -r` hint valid only while inactive. Independent per-run retention is unchanged.
- Setup uses a generous 45-second total deadline to guard against hangs, with Node/npm version checks capped at 10 seconds each, Codex executable probes at 20 seconds, initialization at 30 seconds and auth requests at 20 seconds within the remaining deadline. Optional PATH Codex version/help diagnostics for a broken pin now share that deadline, cap at 20 seconds each and are skipped when no budget remains; setup still reports the broken pin. Standalone availability/auth probes default to a 60-second overall deadline. These limits do not predict startup speed. Stalled Codex probes return unreachable/timeout without suggesting another login; owned probes are terminated and shared brokers are only disconnected.
- Codex App tool sync validates the node executable and readable launcher before writes, including dry-runs and identical definitions. Stale paths now fail without changing config. Tool availability checks the configured CUA executable and reports `cuaReplReason`; optional CUA health remains separate from core `ready` and no live tools are probed.

### Worker names and documentation
